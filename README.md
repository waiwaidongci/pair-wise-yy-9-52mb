# 蓝晒冲洗水回用台

每张底片单独冲洗，回用水缸按“来源 / 容量 / 银盐浓度 / 浊度 / 检测时间”登记，
发许可前自动核用途限值、八小时检测时效与缸时段占用；返工场景可凭底片编号追溯全部用水履历。

## 运行

```bash
npm start          # http://localhost:3040
npm test           # 18 个规则与操作层测试
```

数据落盘在 `data/wash-reuse.json`（可用 `DB_FILE` 覆盖路径，`PORT` 覆盖端口）。

## 业务规则

- **建缸登记**：缸号、来源、容量（升）、用途（预洗 / 显影后 / 定影后）。
- **用途限值**：预洗 银≤50mg/L、浊度≤20NTU；显影后 银≤20、浊度≤10；定影后 银≤10、浊度≤5。
- **冲洗许可**：登记冲洗时依次判定
  1. 同一缸同一时段只接受一张底片（时段首尾相接不算冲突）。重复请求直接 409 指出占用底片，**不写入用量**；
  2. 用途须与缸登记用途一致（选错缸只拒绝，不动缸状态）；
  3. 缸不能处于待复检；
  4. 冲洗开始时刻之前须有八小时内的检测，且银盐、浊度不超过该用途限值。
- **只能待复检**：无检测建档、浓度超限、浊度过高、检测超八小时的缸自动进入待复检。
- **复检放行**：无检测建档的缸一次合格即启用；因指标/时效打回的缸须由**另一名检测人连续两次**合格，
  中间任一不合格从头计数，同人重复提交被拒绝。
- **改单退回重算**：修改检测或变更缸用途时，引用该检测的许可及之后的冲洗记录退回，
  按“冲洗当时之前最近一次检测”的现用途限值与八小时时效逐条重算；合格自动恢复并指向新许可，
  时段冲突则保持退回并记录占用底片，按开始时间先到先得。
- **用水履历**：按底片编号查询有效/退回许可、许可依据检测与每次确认/退回/重算变迁；被拒尝试也留痕。

## 代码分三块

| 文件 | 职责 |
| --- | --- |
| `src/rules.js` | 规则层：限值、八小时时效、用途判定、时段重叠、退回重算，纯函数无 IO |
| `src/archive.js` | 存档层：JSON 落盘、建缸/检测/用量记录的字段校验、审计事件 |
| `src/operations.js` | 操作层：建缸、检测、冲洗登记、复检放行、改单退回与重算、待复检与履历查询 |

`src/page.js` 为页面（只调 API，不含判定）；`server.js` 为 HTTP 路由与错误映射。

## 主要 API

- `POST /api/tanks` 建缸；`GET /api/tanks` 水缸一览；`GET /api/tanks/:id` 缸档案（检测+用量）
- `PATCH /api/tanks/:id/purpose` 改用途（原许可退回重算）
- `POST /api/inspections` 登记检测/复检；`PATCH /api/inspections/:id` 改检测（原许可退回重算）
- `POST /api/washes` 登记冲洗（冲突/超限/超期返回 409，冲突时带 `occupyingNegativeId`）
- `GET /api/pending` 待复检缸及复检进度；`GET /api/negatives/:id/history` 底片用水履历
- `GET /api/events` 审计事件流
